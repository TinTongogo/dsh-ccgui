## ✨ 新功能

### 新建 Worktree（`dbb68ef`）

- **项目右键创建**：左侧栏项目右键新增「新建 Worktree…」，排在 DSH 自己的菜单项前面。三种来源：新分支、已有分支、从 PR 创建。
- **新分支**：从选定的 base 创建，不跟踪 base；base 是远程分支时先 fetch。默认位置是仓库同级的 `<仓库名>-worktrees/<分支名>`，分支名里的空格和 `\/:*?"<>|` 换成 `-`；位置可以改。
- **已有分支**：本地分支直接检出；远程分支先 fetch，再在本地建同名分支并跟踪它（本地已有同名分支时直接用它）。
- **从 PR 创建**：接受 `123`、`#123` 或 PR 链接，从 GitHub 发布的 `refs/pull/<编号>/head` 拉取，不需要 `gh`。有 `upstream` 远程时优先用它（fork 的 PR 在那里）；填链接时按链接里的仓库匹配远程。分支名默认 `pr-<编号>`，手动改过之后，新的 PR 编号不再覆盖它。
- **创建之后**：worktree 加入侧边栏，标题是「仓库名 / 分支名」；勾选「创建后打开新会话」会立刻在里面开会话。Git 拒绝时对话框保持打开并显示原文，比如「分支已存在：…」。
- **侧边栏分组**：worktree 收进所属仓库下面的「Worktrees · N」分组，展开后每个 worktree 一行，再展开是它的会话；分组和行的展开状态记在 localStorage，没有手动选择时，包含当前会话的组自动展开。右键 worktree 或会话弹出的是 DSH 自己的菜单，重命名、删除、置顶、归档都照常可用。
- **嵌套规则**：一个工作区是某个仓库的 worktree、且这个仓库本身也是工作区时，就收进它的分组；在插件之外（比如命令行、CC GUI）建的 worktree 也一样。仓库本身没加成工作区的 worktree 照常显示在顶层。
- **依赖侧边栏结构**：DSH 没有给工作区留嵌套的扩展点，分组是按侧边栏的 `role="tree"` 和 `data-row-key` 插进去的。DSH 改了侧边栏结构时分组会消失，worktree 退回顶层显示，不影响使用。
- **可以关掉**：设置页新增「项目右键新建 Worktree」开关，默认开启。

## 🐛 问题修复

### CLI 会话不再上报 token 用量（`48620bd`，Issue #4）

- ACP 每轮只给一个累计用量，DSH 却把每一步的 usage 当成一次模型请求：速度会被算成整轮输出除以最后一步的耗时，上下文占用会把每次请求的 prompt 累加。数字是错的，所以改为不上报——CLI 会话不显示 tok/s、token 用量和缓存命中，不显示好过显示错的。
- 上下文用量仍然不准，CLI 自己管理上下文；窗口按 1000M 申报，是为了让 DSH 的压缩永远不启动。

### CLI 在协议开始前退出时说明原因（`9ff95e6`）

- CLI 的 stderr 之前是继承的，npm 对启动失败的说明写进 DSH 自己的 stderr，用户看不到。传输层现在收集 stderr 的末尾 4KB，失败信息附带最后 800 个字符和退出码。
- Windows 报出的无符号退出码会附上有符号值，例如 `4294963238（即 -4058）`。
- 启动提示把 npm 的 `Could not read package.json` 也当成安装不完整（npx 碰到上次没装完的缓存目录，不重装就直接失败），并修好 Windows 上带空格路径的识别，「Program Files」不再被截断，能准确给出要删除的 `_npx/<hash>` 目录。

## 📄 文档

- CLI 会话的限制补充：不显示 tok/s、token 用量和缓存命中；DSH 侧的上下文压缩对 CLI 会话不生效，包括 billion-context 这类插件的自动压缩、压缩提醒和 compress / search_context 等工具——CLI 每轮只收到新发的消息，历史存在 CLI 自己那边，DSH 压的是一份 CLI 不读的副本。上下文交给 CLI 自己压缩（比如 Claude Code 的自动压缩）；想让请求经过某个代理，可以在 agent 配置的 `env` 里设置 CLI 认的地址变量，比如 Claude Code 的 `ANTHROPIC_BASE_URL`（`3846aa0`，Issue #5）。
